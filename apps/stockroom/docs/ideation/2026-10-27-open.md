# Ideation: what's worth building next (whole app)

Date: 2026-10-27 · Code as of commit 765eb40 · Focus: none (the whole app)

## Subject

The whole Lyricalmyrical Inventory app: register and Fair Mode, per-book ledgers, consignment, settle-up with authors, invoices, shipping labels, receipts and the Tax Centre. It is an offline-first web app with no framework, Firebase storage, and hosting on GitHub Pages.

Key points from the grounding pass:

- Most recent work (about 35 of the last 60 commits) is the phone "Riso" redesign. Before that came the settle-up money card and some architecture clean-up (carriers folder, shared store, size warning, lazy Open Call).
- `src/main.js` is 20,034 lines and still holds the sync queue, imports, website-order apply and revert, and settle-up maths.
- The offline queue keeps a full copy of each book's state, plus its merge base, in localStorage (`src/main.js:3398-3400`, `src/lib/sync-queue-store.js:11-14`).
- Totals are rebuilt from history on load, live update and merge (`src/main.js:13073`). A few settle actions add to totals directly and skip the rebuild (`src/main.js:10380`, `:10521`, `:10580`, `:8941`).
- There is no import id and no import undo. An unreadable import date silently becomes today (`src/main.js:9778-9783`).
- Several items in the planning notes are still open: the per-year history split, money stored in cents, cross-book settle-up, and offline exchange-rate healing for book expenses.

The ideas came from four angles: pain and friction; removal and automation; leverage; and assumption-breaking, analogy and constraint-flipping. That gave about 40 raw ideas, merged into 25 ideas and 5 combinations. A fresh reviewer then checked every citation against the code.

## Ranked ideas

### 1. Stop the Tax Centre losing expenses typed while it is still loading
**Summary.** Right after the app opens, the Tax Centre shows this device's saved copy and refuses to save until the cloud copy arrives ("try again in a moment"). An expense typed in that window is added on screen, then the save is refused. When the cloud copy lands, it replaces the whole Tax Centre, so the expense quietly disappears. If the cloud load returns nothing, every later save keeps failing. Fix: hold the change, and merge it into the cloud copy once that copy arrives, instead of refusing it.
**Basis.** `direct:` `src/firebase.js:838-841`: `if (key === 'taxCenter' && data && data._preview) { ... showToast('Still loading the latest Tax Centre — try again in a moment' ...); return false; }`. `src/features/tax-entries.js:870`: `TAX_CENTER.businessExpenses.unshift(entry);` runs before the save. `src/main.js:4507`: `TAX_CENTER = { businessExpenses: [], ..., ...json };` replaces the whole object on load.
**Why it matters.** An expense that disappears without warning is a tax deduction lost, and the owner has no reason to look for it.
**Size.** S

```
/supermatt:grill-with-docs Stop the Tax Centre losing expenses typed while it is still loading. Basis: src/firebase.js:838-841 refuses to save the Tax Centre while it is still the startup "_preview" copy and only shows "Still loading the latest Tax Centre — try again in a moment". src/features/tax-entries.js:870 has already added the new expense to memory (TAX_CENTER.businessExpenses.unshift(entry)) before the save. src/main.js:4507 (loadTaxCenter) then replaces TAX_CENTER wholesale when the cloud copy arrives, so the entry is silently dropped. If the load returns nothing, the preview flag never clears and every save fails. Why it matters: a vanished expense is a lost tax deduction that nobody notices. Shape a fix that queues or merges pending changes into the loaded copy, works offline, and has a test.
```

### 2. Safe imports: flag doubtful dates, stamp an import id, undo in one tap
**Summary.** When a spreadsheet is imported, a date the app can't read becomes today's date, and day-first dates such as 03/04 are read month-first without any warning. Nothing records which rows came from which import, so a wrong file can only be undone row by row in History and in the Sheet. The preview should flag guessed or ambiguous dates and ask about them. Each row should carry an import id, and one "Undo this import" action should reverse stock, revenue and the Sheet rows.
**Basis.** `direct:` `src/main.js:9778`: `let parsedDate = today();`, then `:9781-9782`: `const d = new Date(date); if (!isNaN(d)) parsedDate = ...`. `src/main.js:9860`: `addSaleToState(s, book, { ..., stamp: false })` with no batch id. `importId` appears nowhere in `src/`.
**Why it matters.** An import is the biggest single change the owner can make. Today a bad import lands a year of sales on one day, skews the tax and channel figures, and is the most expensive mistake to undo.
**Size.** M

```
/supermatt:grill-with-docs Safe imports: flag doubtful dates, stamp an import id, and undo a whole import in one tap. Basis: src/main.js:9778-9783 sets parsedDate = today() and only replaces it when new Date(date) succeeds, so unreadable dates silently become today and day-first dates (03/04) are read month-first. src/main.js:9860 (confirmImport → addSaleToState, stamp:false) records no import id, and grep finds no importId or import undo in src/. Why it matters: a wrong import corrupts per-year tax and sales figures and today can only be undone row by row in History and the Google Sheet. Decide how the preview flags dates, where the import id lives, and what undo must reverse (stock, revenue, consignment, Sheet rows).
```

### 3. Keep offline fair sales safe even on a full phone
**Summary.** The offline queue stores a full copy of the book, plus its merge base, in the browser's small storage area (about 5 MB). On a big book that write can fail. The sale then exists only in memory, and the only warning is "keep the app open until it uploads". Move the queue to the browser's larger database storage, which the app already uses for receipts. Ask the browser to keep that data permanently. Over time, queue the change itself rather than the whole book.
**Basis.** `direct:` `src/main.js:3398-3400`: `bookId, state: JSON.parse(JSON.stringify(state)), ts: Date.now(), base,`. `src/lib/sync-queue-store.js:11-14`: "Queue items are whole book states and can be large, so a write can fail with QuotaExceededError." `src/main.js:3234-3235`: "...couldn't be saved on it. Keep the app open until it uploads, or it could be lost." `external:` MDN, "Storage quotas and eviction criteria" and `StorageManager.persist()`. `navigator.storage.persist` is never called. The reviewer noted the queue keeps only the latest copy per book, so it does not grow with each edit, and that a "waiting to upload" count already exists. The risk comes from book size, not from the number of edits.
**Why it matters.** Not losing a sale with no signal is the reason an offline register exists. Here the warning only arrives once it is too late.
**Size.** M

```
/supermatt:grill-with-docs Keep offline fair sales safe on a full phone: move the sync queue from localStorage to IndexedDB and request persistent storage. Basis: src/main.js:3398-3400 queues a deep copy of the whole book state plus its merge base; src/lib/sync-queue-store.js:11-14 says writes can fail with QuotaExceededError; src/main.js:3234-3235 then only warns "Keep the app open until it uploads, or it could be lost". IndexedDB is already used for receipts (src/features/receipts.js:244); navigator.storage.persist() is never called (MDN: localStorage ≈5 MiB/origin, IndexedDB a share of disk). The queue keeps one latest copy per book (src/main.js:3374-3376). Why it matters: a lost offline sale is exactly what the app promises won't happen. Decide migration of existing queued items, synchronous-read needs at startup, and whether to queue operations instead of snapshots.
```

### 4. A two-device "flaky network" test that hunts for lost or doubled sales
**Summary.** Write a test with a seeded random generator and no new libraries. It plays thousands of random sequences on two simulated devices: sell, edit, void, go offline, reconnect, upload. After each run it checks that no sale was lost or doubled, and that the saved totals match a fresh rebuild from history. Any failing seed is kept as a permanent test. Fold in the small fix it would catch first: four settle and website-update actions change the totals without rebuilding them afterwards.
**Basis.** `external:` property-based testing (QuickCheck, Claessen & Hughes 2000) and history checking (Jepsen). `direct:` the merge's own special cases, `src/lib/merge-state.js:250-277`. Totals change without a rebuild at `src/main.js:10380`, `:10521`, `:10580` (`s.revenue += t.total;`) and at `:8941-8945` (`reapplyOne`), while everything else runs `recalculateBookStatsFromHistory` (`src/main.js:13073`). `src/lib/merge-state.js:84-88` documents a known gap where an edit made on two devices keeps both versions.
**Why it matters.** The owner merges automatically once checks are green, so the checks have to be what catches a lost or double-counted sale. This test also makes ideas 2 and 3 safe to ship.
**Size.** M

```
/supermatt:grill-with-docs A seeded two-device "flaky network" test for the sync queue and merge, plus making the four direct-total sites rebuild. Basis: src/lib/merge-state.js:250-277 has hand-written union/sum special cases and :84-88 documents that concurrent edits to uid-less rows keep both versions; src/main.js:10380, :10521, :10580 (s.revenue += t.total) and :8941-8945 (reapplyOne) change totals without calling recomputeAfters / recalculateBookStatsFromHistory (src/main.js:13073). Prior art: QuickCheck-style property testing, Jepsen history checks — hand-written seeded RNG, no new deps, Vitest. Why it matters: the owner auto-merges on green CI, so CI must catch lost or doubled sales. Decide which functions the model drives (queueSync, processSyncQueue, mergeState), the invariants, and how failing seeds become fixtures.
```

### 5. Consignment rounds: chase quiet stores, then record a visit by counting the shelf
**Summary.** The To-do only mentions a store once it owes money. A shop that never reports sales owes nothing on paper, so twelve copies can sit there for a year unnoticed. Add a signal for stores that have copies out and no report in a set number of days, with a ready-to-send check-in note. Then change how a visit is recorded. The owner enters how many copies of each title are still on the shelf, across all books at that store. The app works out what sold, records it, and drafts one invoice.
**Basis.** `direct:` `src/lib/attention-signals.js:163-167` sums `st.amountOwed` and only adds a signal `if (owed > 0)`. `src/main.js:11877-11878` asks for the sold quantity per book (`Only ${st.outstanding} outstanding`). `src/main.js:11330`: `export function getConsignmentStoresAcrossBooks()` already gathers stores across books. `external:` library overdue notices (for example, Koha's loan due dates).
**Why it matters.** Copies at stores are the biggest unsupervised stock a small publisher has. Counting the shelf is what the owner actually does in the shop, so the app should match that.
**Size.** M

```
/supermatt:grill-with-docs Consignment rounds: a "quiet store" To-do signal with a drafted check-in note, feeding a shelf-count store visit that derives sold copies across all books and drafts one invoice. Basis: src/lib/attention-signals.js:163-167 only signals stores with amountOwed > 0; src/main.js:11877-11878 makes the owner type a sold qty per book per store ("Only N outstanding"); src/main.js:11330 getConsignmentStoresAcrossBooks() already gathers a store across books. Analogy: library loans with due dates and overdue notices. Why it matters: unchased consignment copies are the biggest unseen stock loss, and counting the shelf matches what the owner does in the shop. Decide the "quiet" threshold, how a visit writes sales into each book's ledger offline, and the invoice hand-off.
```

### 6. Book expenses logged offline: fill in the exchange rate later, and show "paid back" in exports
**Summary.** A foreign-currency book expense logged offline is saved with no Canadian-dollar value and a "rate missing" flag. Business expenses get that rate filled in later, but book expenses never do. So settle-up leaves them out, with a note telling the owner to pay them separately, and the Tax Centre counts them as zero. Separately, whether an expense was paid back to an author in settle-up only shows in a hover tooltip, and never appears in exports.
**Basis.** `direct:` `src/main.js:9514`: `for (const e of (TAX_CENTER.businessExpenses || [])) {` heals business expenses. `src/main.js:9529`: `if (!e || e.gratuity !== true || e.voided) return false;` heals only gifted copies among book expenses. `src/features/tax-entries.js:861-867` saves offline entries with `baseAmount` null and `fxMissing`. `src/features/receipts.js:7981`: `title="Paid back in the author settlement of ..."` is tooltip only.
**Why it matters.** An author's settle-up silently drops a real cost, and the accountant's export can't show which expenses the author already repaid.
**Size.** S

```
/supermatt:grill-with-docs Heal the exchange rate for ordinary per-book expenses logged offline, and put "paid back in author settlement" into exports. Basis: src/main.js:9514 heals only TAX_CENTER.businessExpenses and src/main.js:9529 only gifted-copy (gratuity) book expenses, so a non-gifted book expense saved offline with baseAmount null + fxMissing (src/features/tax-entries.js:861-867) is never filled in; settle-up then excludes it with a "pay separately" note (src/lib/settle-up-view.js:212-214) and the Tax Centre counts it as 0. "Paid back" shows only as a tooltip at src/features/receipts.js:7981 (derived by expensesWithSettlements in receipt-storage.js:295-301). Why it matters: an author's settlement silently omits a real cost, and the accountant can't see repaid expenses. Decide which exports get the column and how the settle-up note is reworded.
```

### 7. Shorten the All Books page on a phone
**Summary.** On a phone, All Books is about 8,000 pixels tall, roughly six screens of scrolling before the owner reaches the consignment summary and the filter. Put each book's channel breakdown behind a "Show channels" control, the way the Dashboard already does. Move the summary and filter to the top, and consider a dense one-line-per-book view.
**Basis.** `direct:` `docs/phone-redesign-round-3.md:70-71`: "The All Books screen is roughly 8,000 px tall on a phone." It is still marked Open, and grep finds no "Show channels" control.
**Why it matters.** It is the longest screen in the app, and the owner checks the phone layout first.
**Size.** S

